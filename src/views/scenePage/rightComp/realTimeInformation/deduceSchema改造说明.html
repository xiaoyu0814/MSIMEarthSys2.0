deduce 消息 · 字段结构改造说明

目录 src/views/scenePage/rightComp/realTimeInformation/

改动目标： 之前 deduce 消息（传感器异常 / 飞机颠簸 等）中，字段列表是在 index.vue 中硬编码的对象结构，"传感器名称" 对所有异常类型都显示（不区分传感器 vs 飞机），且颜色 / 截断 / 颜色映射混在模板里，后续新增异常类型要同时改三个地方。 本次改造把 "字段列表、颜色、截断、显示条件" 统一抽取到独立的 schema 文件集中管理。

一、改动总览

操作 文件 说明
✅ 新增 deduceMessageSchemas.js 按异常类型 → 字段定义 schema 集中管理；暴露 getDeduceSchema() / buildDeduceFields() 两个方法
✅ 修改 index.vue 导入 schema；消息构建处从"手写 temp 对象"改为"按 schema 构建"；模板从"多个 v-if 硬编码字段"改为"遍历 _fields 数组"

二、新文件：deduceMessageSchemas.js

2.1 字段定义对象结构

每个字段是一个对象，配置渲染行为：

属性 类型 说明
label string 左侧显示的中文标签
valueKey string 从 newValue 中直接取值的字段名
transform(ctx) function 自定义取值函数，与 valueKey 二选一
type string 渲染类型： text 普通文本（默认） severity 彩色数字 side 阵营 details 详情（超长省略号）
truncateLen number 截断字符数，默认 20
showIf(ctx) function 返回 false 时该字段不显示

2.2 统一的映射表

SIDE_MAP { red: '红', blue: '蓝', green: '绿', purple: '紫' }
SIDE_COLOR_MAP { 红: '#ff4d4f', 蓝: '#1890ff', 绿: '#52c41a', 紫: '#b488ff' }

2.3 Schema 匹配规则 getDeduceSchema(abnormalTypeCode)

  1. 精确匹配：deduceSchemaMap[type] —— SENSOR / TURBULENCE 等已有独立定义
  2. 前缀匹配：以 SENSOR 开头的（如 SENSOR_CONNECTION_TIMEOUT、SENSOR_NO_RESPONSE）统一走 SENSOR schema
  3. 飞机异常 fallback：其余所有未定义的 → planeAbnormalSchema
  4. 兜底：完全未知 → defaultSchema

2.4 公共字段定义（可复用）

变量 label 显示条件
fieldPlatformName 装备名称 始终显示；传感器异常取 platformType，其他取 platformCName
fieldSensorName 传感器名称 ✅ 传感器相关异常均显示 （showIf: abnormalTypeCode.startsWith('SENSOR')，如 SENSOR / SENSOR_CONNECTION_TIMEOUT 等）
fieldSide 阵营 彩色中文；颜色由 SIDE_COLOR_MAP 决定
fieldTime 时间 HH:mm:ss 格式
fieldPosition 位置 经纬度+高度
fieldAbnormalType 影响类型 newValue.abnormalTypeCName
fieldDetails 详情 超长省略号，悬停显示完整文本
fieldSeverity 影响等级 只显示彩色数字（如 "6"）

三、index.vue 的改动

3.1 import 区新增

import {
  getDeduceSchema,
  buildDeduceFields
} from './deduceMessageSchemas.js'

3.2 deduce 消息构建（原硬编码 temp 对象）

改造前

let temp = {
  装备名称: name,
  传感器名称: newValue.sensorName || '',
  阵营: sideCN,
  时间: getTime(time, 'HH:mm:ss'),
  位置: `${newValue.longitude.toFixed(3)}°E,...`,
  影响类型: newValue.abnormalTypeCName,
  详情: displayDetails,
  影响等级: threatLevels[newValue.severity - 1]
}
czmlEventSourceData.msg = JSON.stringify(temp)

改造后

const schema = getDeduceSchema(newValue.abnormalTypeCode)
const ctx = { newValue, side, name, time, getTime, threatLevels }
const fields = buildDeduceFields(schema, ctx)
const temp = { _fields: fields }
for (const f of fields) temp[f.label] = f.value   // 向后兼容
czmlEventSourceData.msg = JSON.stringify(temp)

说明：_fields 是供模板遍历渲染的主数据源；temp[f.label] = f.value 扁平拷贝是为了保持对其他可能消费该消息对象的地方（如有）不报错。

3.3 模板渲染

改造前

v-for="(value, key, idx) in safeParseJson(seg)"
  v-if="key == '影响等级'"  →  彩色 + level
  v-else-if="key == '阵营'"    →  颜色硬编码映射
  v-else                         →  普通文本 + 省略号（详情单独处理 title

改造后

v-for="(row, idx) in (safeParseJson(seg)._fields || [])"
  v-if="row.type === 'severity' || row.type === 'side'"
    ：color = row.color
  v-else
    ：class="env-value truncate-value"

模板只关心"字段是彩色还是省略号文本，不再区分具体字段名。

四、整体数据流向

  1. newValue 消息到达
  2. getDeduceSchema(abnormalTypeCode) → 字段定义数组
  3. buildDeduceFields(schema, ctx) → 渲染用 row 数组（label / value / color / _fullText）
  4. JSON.stringify({ _fields: rows }) → 存入 czmlEventSourceData.msg
  5. 模板中 safeParseJson(seg)._fields 取出 row 数组 v-for 遍历渲染

六、为什么这样改造带来的好处

场景 之前 现在
传感器名称显示控制 所有异常都显示（不区分传感器/飞机），且在装备名称之后 ✅ 仅传感器相关异常显示；字段位置调整到"影响类型"下方，语义更清晰
影响等级只显示数字 多个 v-if 写死 schema 层统一处理
颜色映射 模板里硬编码颜色对象 schema 层统一管理
字段超长省略 硬编码 truncateLen=20 每个字段可独立配置
新增异常类型 至少改 3 处（构建/template/style） 只需在 deduceSchemaMap 加一项（或零改动）
字段顺序调整 改模板的顺序/字段对象键值 改 schema 数组顺序

八、更新记录

2026-06-12 · 第2次更新 —— 传感器名称字段调整

  1. SENSOR schema 字段顺序调整

    传感器名称从"装备名称之后"移至"影响类型之后"，视觉上强化了"传感器异常"这个影响类型的语义。

    调整前顺序：装备名称 → 传感器名称 → 阵营 → 时间 → 位置 → 影响类型 → 详情 → 影响等级

    调整后顺序：装备名称 → 阵营 → 时间 → 位置 → 影响类型 → 传感器名称 → 详情 → 影响等级

  2. fieldSensorName 的 showIf 扩展

    abnormalTypeCode === 'SENSOR' → abnormalTypeCode.startsWith('SENSOR')

    SENSOR、SENSOR_CONNECTION_TIMEOUT、SENSOR_NO_RESPONSE 等所有传感器相关异常，现在都会显示传感器名称字段。

  3. 设计原则

    每个影响类型（如传感器异常、飞机颠簸、高度异常等）都可以有自己的专属字段。专属字段统一放在"影响类型"行下面，使消息结构逻辑一致。后续新增其他影响类型的专属字段时，只需：

    1. 在 deduceMessageSchemas.js 顶部定义一个新的 fieldXXX，配置 label / transform / showIf
    2. 在对应类型的 schema 数组中，将它放在 fieldAbnormalType 后面
    3. 无需修改模板 / CSS / 组件代码
